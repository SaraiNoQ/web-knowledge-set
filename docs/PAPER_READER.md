# 论文知识与逐页对照阅读

状态：论文数据域与分页阅读器已接入；当前持续补充真实 PDF/LLM 兼容性验证与发布证据。

## 目标

把论文作为一种独立知识类型保存，不强行套用现有“网页文章 + Markdown”工作流。用户可以用公开论文链接（优先 arXiv 等可直接获取的来源）或上传 PDF 建立一条论文知识记录，然后以原文页和中文译文页一一对应的方式阅读。

## 首版边界

- 来源：公开 `http(s)` 论文链接，或用户主动选择的 PDF 文件。
- 处理：服务端调用“AI 设置”里已经配置的 LLM；模型负责从整份论文中返回分页结构、正文、表格/公式占位和图片资源引用。
- 阅读：按页切换；桌面优先采用左原文、右译文的对照布局，同时保留 PDF 页码、章节目录和处理状态。
- 保存：原始来源不可被 AI 覆盖；提取结果按一次处理任务保存，可重新生成新版本。
- 失败：没有可用模型、模型不支持 PDF/视觉输入、输出不符合分页结构或资源校验失败时，明确停在失败状态，不伪装成普通文章。

PDF.js 只负责显示原始页，不负责正文抽取；论文正文、译文和图表说明由已配置的多模态 LLM 生成。

## 建议的数据形状

```text
paper
├─ source: url | uploaded-pdf
├─ originalFile / originalUrl
├─ metadata: title, authors, venue, publishedAt
├─ extraction: queued | processing | ready | failed
└─ pages[]
   ├─ pageNumber
   ├─ original: blocks[]
   ├─ translation: blocks[]
   └─ assets[]
```

`blocks[]` 至少需要 `heading`、`paragraph`、`formula`、`table`、`figure`、`caption`、`reference` 这些类型；不要把整页重新拼成一段 Markdown，否则无法稳定保持页码、图表和中英文对照关系。

## 处理流程

1. 用户提交公开 URL 或 PDF，先校验来源、大小、类型和重复论文。
2. 保存原始来源并创建 `queued` 任务；原文文件始终作为只读证据保留。
3. 以结构化输出提示调用已配置 LLM。首选能直接接收 PDF 的多模态模型；不支持该能力的模型首版直接提示“不支持”，不偷偷引入本地 PDF 解析器。
4. 校验模型返回的 JSON：页码必须连续或明确缺页，所有块必须归属页，图片/表格引用必须可追溯。
5. 分页保存原文提取结果、译文结果和图片资源；阅读器按 `pageNumber` 切换，不用滚动位置猜测两侧是否同步。

当前 DeepSeek `chat/completions` 端点的文件输入仅适用于视觉模型的图像文件，不接受本功能发送的 PDF；使用该端点时会在提取前返回“当前模型不支持论文 PDF 输入”，不会消耗模型请求，也不会把失败误报为分页 JSON 错误。需要处理 PDF 时，请在 AI 设置中切换到明确支持 PDF `file` content-part 的模型或端点。

## PDF 兼容路线

建议按三层处理，而不是让每个模型都走同一份请求体：

1. **能力登记与端点适配**：为 AI 端点保存 `pdf-input`、`image-input`、`json-output` 能力；请求前按能力选择 PDF file-part、图片 content-part 或明确失败。原始 PDF 始终保留，不能用模型输出替代证据。
2. **优先切换兼容模型**：支持 PDF 的模型直接走逐页结构化提取，质量和图表理解最好，也不需要在 Worker 中安装 PDF 解析器。
3. **受控降级（后续可选）**：对文本模型，在独立的预处理 Worker/队列中把 PDF 按页转成“页图 + OCR/文本”，再分批发送；必须记录预处理版本、页码、OCR 置信度和成本，并允许用户只重做失败页。不要把这个降级路径隐式混入首版，否则会带来字体、公式、表格和大文件内存边界。

当前版本先对已知不支持 PDF 的 DeepSeek Chat Completions 端点做请求前拦截，并对其他端点沿用统一失败校验；通用能力登记和第 3 层降级应作为单独里程碑，用真实论文样本验证后再开启。

## 结构化输出约束（草案）

```json
{
  "schemaVersion": 1,
  "paper": { "title": "", "authors": [], "source": "" },
  "pages": [
    {
      "pageNumber": 1,
      "blocks": [
        {
          "id": "p1-b1",
          "type": "paragraph",
          "original": "",
          "translation": "",
          "assetIds": []
        }
      ]
    }
  ],
  "assets": [{ "id": "fig-1", "kind": "figure", "data": "" }]
}
```

这个契约先服务于分页阅读，不承诺逐字坐标级对齐。公式、图表和参考文献必须保留原文；翻译只作为并列内容，不改写原始页。

## 页面方案

- 导入：一个入口，URL 与 PDF 上传是两个 tab；旁边明确说明来源、文件大小和 AI 发送范围。
- 处理中：显示“原始文件已保存 / 正在提取分页结构 / 正在生成译文 / 资源校验”的阶段，而不是只显示一个旋转图标。
- 阅读：左侧页缩略图，中间原文/译文对照页，右侧章节目录、来源、处理版本和资源数；底部使用页码上一页/下一页控制。
- 状态：原文可读但翻译失败时仍允许只看原文；任意页缺译文都标注缺失，不用空白占位掩盖失败。

## 待确认问题

1. 首版目标 LLM 是否必须支持直接上传 PDF，还是允许服务端先把 PDF 页转成图片再发给视觉模型？这会决定是否需要引入 PDF 渲染依赖。
2. 翻译结果是否只读并按版本保存，还是允许用户在页内编辑译文？建议首版只读，编辑作为后续派生版本。
3. 原文展示优先采用浏览器 PDF 预览还是页面级图片？前者实现快，后者更容易与译文页严格同步。
4. 论文图片是否保存原图，还是只保存 LLM 生成的图片说明？建议原图与说明分开保存，避免模型输出替代证据。
5. 论文与现有文章之间是否需要互相链接，还是先保持两个独立知识类型？建议首版独立，避免现有 Markdown 结构被论文分页模型污染。
