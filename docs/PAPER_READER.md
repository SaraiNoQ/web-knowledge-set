# 论文知识与逐页对照阅读

状态：论文数据域与分页阅读器已接入；当前持续补充真实 PDF/LLM 兼容性验证与发布证据。

## 目标

把论文作为一种独立知识类型保存，不强行套用现有“网页文章 + Markdown”工作流。用户可以用公开论文链接（优先 arXiv 等可直接获取的来源）或上传 PDF 建立一条论文知识记录，然后以原文页和中文译文页一一对应的方式阅读。

## 首版边界

- 来源：公开 `http(s)` 论文链接，或用户主动选择的 PDF 文件。
- 处理：服务端调用“AI 设置”里已经配置的 LLM；模型接收整份 PDF，或接收由浏览器逐页渲染的页图，并在每个批次里返回该批次的原文块、译文、表格/公式占位和图片资源引用。
- 阅读：按页切换；桌面优先采用左原文、右译文的对照布局，同时保留 PDF 页码、章节目录和处理状态。
- 保存：原始来源不可被 AI 覆盖；提取结果按一次处理任务保存，可重新生成新版本。
- 失败：没有可用模型、模型既不接受 PDF 也不接受图片、输出不符合分页结构或资源校验失败时，明确停在失败状态，不伪装成普通文章。

PDF.js 负责显示原始页，同时是页图的唯一渲染器：Worker 与本地 Node 服务都不引入 PDF 光栅化依赖，页图只能来自浏览器。论文正文、译文和图表说明由已配置的多模态 LLM 生成。

## 建议的数据形状

```text
paper
├─ source: url | uploaded-pdf
├─ originalFile / originalUrl
├─ metadata: title, authors, venue, publishedAt
├─ extraction: queued | processing | ready | failed
└─ pages[]
   ├─ pageNumber
   ├─ original: blocks[]
   ├─ translation: blocks[]
   └─ assets[]
```

`blocks[]` 至少需要 `heading`、`paragraph`、`formula`、`table`、`figure`、`caption`、`reference` 这些类型；不要把整页重新拼成一段 Markdown，否则无法稳定保持页码、图表和中英文对照关系。

## 处理流程

1. 用户提交公开 URL 或 PDF，先校验来源、大小、类型和重复论文。
2. 保存原始来源并创建 `queued` 任务；原文文件始终作为只读证据保留。
3. 以结构化输出提示调用已配置 LLM。默认先发整份 PDF；端点已知不接受 PDF（DeepSeek `chat/completions`）、或 PDF 请求被拒、或整篇超出单次回答上限时，改发浏览器渲染的逐页图片。两种方式都不引入服务端 PDF 解析器。
4. 校验模型返回的 JSON：页码必须连续或明确缺页，所有块必须归属页，图片/表格引用必须可追溯。
5. 图片通道按批（默认 4 页）保存：每个批次的原文块、译文和页码立即落库，`completed_pages` 随批次前进，阅读器按 `pageNumber` 切换，不用滚动位置猜测两侧是否同步；中途失败保留已完成页，重新提取从已完成页继续。

DeepSeek `chat/completions` 不接受 PDF 文件输入，但对视觉模型接受 `image_url` content-part，因此该端点直接被路由到图片通道：不会先发一次注定被拒的 PDF 请求；该端点上的论文请求还会显式关闭思考模式（与自动标题一致），否则输出预算可能被推理过程吃光而返回空回答。图片通道要求先把每页渲染成 JPEG 并上传，页图按 PDF 内容哈希存放（云端 R2 `paper-pages/<hash>/<页码>.jpg`，本地数据目录同名路径），只在需要时渲染，已渲染页不会重复渲染。若端点既不接受 PDF 也不接受图片，会返回 `PAPER_MODEL_NO_VISION`，请在 AI 设置中改用支持视觉的模型。

## PDF 兼容路线

按三层处理，而不是让每个模型都走同一份请求体：

1. **能力路由**：按端点决定先发 PDF 还是直接发页图；只有端点明确不接受 PDF 时才改变发送方式，其余端点默认走 PDF。原始 PDF 始终保留，不能用模型输出替代证据。
2. **整篇 PDF 优先**：端点接受 PDF 时一次发送整篇，图表理解最好，也不需要在 Worker 中安装 PDF 解析器。
3. **页图分批（已实现）**：PDF 被拒或整篇放不进单次回答时，浏览器用 PDF.js 逐页渲染 JPEG 并上传，服务端按批发送 `image_url` content-part；单批被截断或结构不可用时二分收窄，单页仍放不下则返回 `PAPER_PAGE_OVERFLOW`。页图是派生缓存，不进备份包，永久删除最后一篇引用该 PDF 的论文时一并清除。

第 3 层保留了原始 PDF，并且每一批都要求页码与请求一致，因此模型无法通过删页或重编号来掩盖失败。

## 结构化输出约束（草案）

```json
{
  "schemaVersion": 1,
  "paper": { "title": "", "authors": [], "source": "" },
  "pages": [
    {
      "pageNumber": 1,
      "blocks": [
        {
          "id": "p1-b1",
          "type": "paragraph",
          "original": "",
          "translation": "",
          "assetIds": []
        }
      ]
    }
  ],
  "assets": [{ "id": "fig-1", "kind": "figure", "data": "" }]
}
```

这个契约先服务于分页阅读，不承诺逐字坐标级对齐。公式、图表和参考文献必须保留原文；翻译只作为并列内容，不改写原始页。

## 页面方案

- 导入：一个入口，URL 与 PDF 上传是两个 tab；旁边明确说明来源、文件大小和 AI 发送范围。
- 处理中：显示“原始文件已保存 / 正在确认发送方式 / 正在渲染页图 x/y / 正在生成分页对照 x/y”的实际阶段与进度，而不是只显示一个旋转图标。
- 阅读：左侧页缩略图，中间原文/译文对照页，右侧章节目录、来源、处理版本和资源数；底部使用页码上一页/下一页控制。
- 状态：原文可读但翻译失败时仍允许只看原文；任意页缺译文都标注缺失，不用空白占位掩盖失败。
