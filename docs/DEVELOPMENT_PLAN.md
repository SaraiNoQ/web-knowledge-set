# 织页 v1.0 完整开发计划

## 1. 目标与边界

织页 v1.0 是一个本地优先、单用户的互联网知识库：用户能够安全采集公开网页，把正文和必要资源保存为可离线阅读、可编辑、可检索和可迁移的知识，并通过签名、公证的 macOS 应用长期使用。

v1.0 坚持以下边界：

- SQLite 是唯一事实源；Markdown 和 ZIP 是导入导出格式，不是运行时双向同步目录。
- 服务仅监听随机 `127.0.0.1` 端口，不提供账号、多用户、局域网访问或云同步。
- 默认不向任何 LLM 发送数据；AI 功能必须由用户显式启用、预览输入范围并手动采纳结果。
- 不支持登录态网页、Cookie 导入、付费墙或验证码绕过，也不抓取内网地址。
- v1.0 不做浏览器扩展、移动端、Windows/Linux 正式包、协作、云同步、知识图谱、向量检索和自动 Agent。它们进入 v1.1 候选池，并以真实需求为准。
- 所有常规依赖安装、编译、测试和开发服务都在 `root@campus-server:/root/dev/zhiye` 进行。本地工作区只编辑与同步源码。
- Linux 服务器负责平台无关验证和 Tauri/Linux 编译检查；Apple 签名、公证及最终 macOS 包必须在受控 macOS CI runner 上完成，这是发布阶段的必要平台例外。

## 3. 统一开发与交付规则

### 3.1 里程碑工作流

每个里程碑必须按同一流程交付：

1. 从已验证的上一里程碑开始，只实现本阶段范围。
2. 在本地编辑源码后，以排除依赖、产物、测试报告和数据目录的方式同步到 `campus-server:/root/dev/zhiye`。
3. 在服务器使用锁定的 Node/pnpm 版本安装或复用依赖，执行本阶段列出的全部门槛。
4. 由未参与该实现的独立 agent 审查完整未提交 diff，重点检查正确性、安全、数据丢失、迁移兼容、测试覆盖和不必要复杂度。
5. 修复审查发现，重新执行受影响门槛；全部通过后再创建一个或多个聚焦的 Conventional Commit。
6. 检查提交内容与工作树，推送至 `git@github.com:SaraiNoQ/web-knowledge-set.git`。里程碑结束时必须有可回退的 Git 标签或明确提交 SHA。

任何迁移、备份/恢复、删除、导入、资源清理和自动更新变更都属于高风险变更，不能与无关 UI 修改放在同一提交中。

### 3.2 每阶段共同门槛

除阶段特有门槛外，每次提交前至少在 `campus-server` 通过：

- 冻结锁文件安装；TypeScript 类型检查；Node 单元与集成测试；生产构建。
- 涉及用户路径时运行 Playwright E2E；涉及 Chromium 时安装的浏览器版本必须与锁文件一致。
- 涉及 Rust/Tauri 时运行格式检查、Clippy（警告视为错误）和可用平台的编译检查。
- 从上一发布版本数据库副本启动并迁移；失败不得改坏原副本。
- `git diff --check`，且源码同步中没有 `node_modules`、构建产物、浏览器缓存、测试报告或真实用户数据。

### 3.3 版本策略

- `v0.1.x`：冻结与修正现有 MVP 基线。
- `v0.2` 至 `v0.6`：按下面阶段逐步完成正式能力。
- `v0.9.0`：功能冻结的候选版，只接受缺陷、文档和发布工程修改。
- `v0.9.1`：锁定正式应用身份并安全承接早期开发数据的无签名候选版；不宣称已上线。
- `v0.9.2-rc.1`：阶段 A 功能完整预览版；稳定 Web 和未签名 Apple Silicon 包，不包含正式自动更新能力。
- `v1.0.0`：阶段 B 正式版；Apple 签名、公证、更新实测和本文 Definition of Done 全部满足后发布。数据库迁移只能前向追加，不修改已经发布的迁移。

**具体功能**

- 完成 README 中的首次启动、SSH 隧道、数据目录和已知限制说明。

**技术工作**

- 将 `origin` 设为 `git@github.com:SaraiNoQ/web-knowledge-set.git`，记录基线提交和 `v0.1.0-mvp` 标签。
- 锁定 Node、pnpm、Rust/Tauri 和 Chromium 版本；确保冻结锁文件可从干净服务器环境安装。
- 增加一个统一 `verify` 命令，仅串联现有检查，不另建任务框架。
- 保存从空库、当前迁移版本和中断抓取状态启动的测试基线。
- 保护 `main` 并禁止强推；先以 campus-server 验证记录作为 PR 门禁，只有配置同一台服务器的自托管 runner 后才启用 required status checks，禁止改用 GitHub 托管 runner 安装依赖或构建。

**验收与测试门槛**

- 从进程中断恢复后，任务不会永久卡在运行中，人工正文不会被重抓覆盖。
- Git 工作树干净，远端可拉取，基线标签指向已验证提交。

**依赖**

- 当前 MVP；可访问 GitHub 的 SSH 凭据。

**提交 / Review 边界**

- `chore(repo): establish reproducible mvp baseline`
- 如发现阻断缺陷，以独立 `fix(...)` 提交交付；每个提交均在服务器复验并由独立 agent 审查。

### M1：数据生命周期、备份与恢复（v0.2.0）

**用户价值**

用户可以放心长期积累知识：误删可恢复，升级前自动留档，机器或数据库故障后有明确恢复路径。

**具体功能**

- 文档回收站、恢复和永久删除；v1.0 不自动清空回收站，永久删除必须由用户二次确认。
- 手动创建完整备份、查看备份时间/大小/校验状态、从备份恢复。
- 每日首次启动自动备份、迁移前强制备份和可配置保留数量；空间不足时明确失败，不继续迁移。
- 数据健康页：数据库完整性、快照/资源缺失、孤儿文件、当前存储占用和最近备份结果。
- 退出与崩溃后任务恢复；不完整的临时备份和孤儿快照可安全清理。

**技术工作**

- 只追加迁移：增加软删除时间、备份记录和必要索引；所有查询默认排除回收站。
- 备份时暂停新写入与采集，使用 SQLite 一致性副本，并将数据库、快照和带版本的 manifest 写入临时目录；校验哈希后原子改名。
- 恢复只能在服务维护模式执行：先验证 manifest、文件哈希、格式版本和可用空间，再保留当前数据的恢复前备份，最后原子切换。
- 数据目录、备份、临时文件采用最小权限；绝不把备份或真实数据加入 Git。
- 永久删除在事务中解除引用，提交后再回收无引用文件；失败时下次启动继续垃圾回收。
- 每个已发布 schema 版本保留最小迁移 fixture，迁移函数不可回写历史 migration。

**验收与测试门槛**

- 备份后新增/修改/删除数据，再恢复，文档、标签、采集历史、快照及修订号逐项一致。
- 在复制中断、磁盘空间不足、校验失败和损坏 SQLite 情况下，原数据仍可启动且错误可读。
- 从所有已发布 schema fixture 升级到当前版本，重复启动不重复迁移。
- 删除后资源引用计数正确；回收站恢复不丢内容，永久删除后无数据库孤儿和未引用快照。
- `PRAGMA integrity_check`、外键检查和备份 manifest 校验全部通过。

**依赖**

- M0 基线；稳定的数据目录锁与任务暂停机制。

**提交 / Review 边界**

- 提交一：`feat(data): add recoverable document lifecycle`，只含迁移、回收站和测试。
- 提交二：`feat(backup): add verified backup and restore`，只含备份/恢复、健康检查和破坏性场景测试。
- 每个提交先做独立 agent 数据丢失审查，再在服务器执行恢复演练后提交。

### M2：采集可靠性、历史与离线资源（v0.3.0）

**用户价值**

更多公开网页能稳定转为高质量 Markdown；文章和主要图片在断网时仍可阅读，用户能看见每次采集发生了什么并安全重试。

**具体功能**

- 采集历史列表：时间、耗时、模式、状态、最终 URL、HTTP 状态、警告、错误和快照。
- 从已有 HTML 快照重新提取，无需重新联网；展示新旧结果差异，必须由用户选择是否替换人工标题/正文。
- 下载正文引用的图片供离线预览；失败图片保留原 URL 和明确状态，不导致文章导入整体失败。
- 可暂停/继续队列、取消尚未开始的任务、对失败任务重试；保持单任务执行，直到真实数据证明需要并发。
- 重复 URL 和 canonical URL 提示合并或保留，不静默复制或覆盖。
- 提取质量页显示低正文、缺标题、资源失败等可操作警告。

**技术工作**

- 新增 `assets` 与文档资源关联表；资源以内容哈希命名并去重，保留原 URL、MIME、字节数、哈希和抓取状态。
- 图片下载复用安全出站网关，逐次 DNS/重定向校验；仅允许校验过魔数的 JPEG、PNG、GIF、WebP、AVIF，v1.0 不缓存 SVG、脚本、CSS 或视频。
- 默认限制：单资源 10 MiB、每篇 100 个资源、每篇资源总量 100 MiB、进程内最多 3 个资源请求；这些值进入本地设置且有硬上限。
- Markdown 正文继续保留标准远程 URL；预览优先通过文档资源映射加载本地文件，便携 ZIP 导出时才改写为相对路径。
- 资源 API 使用不可猜测或哈希 ID、正确 MIME、`nosniff` 和强 CSP，不接受任意文件路径。
- 保存提取器版本；重新提取生成候选结果和 diff，不直接更新文档。
- 建立固定中英文样本：文章、分页噪音、表格、代码、数学、响应式图片、懒加载图、畸形 HTML、JS 页面和恶意资源。

**验收与测试门槛**

- 固定样本的标题/正文/代码块/表格达到已记录的结构断言，升级提取器时必须通过回归。
- 关闭网络后，已缓存文章正文与允许类型图片正常显示；缺失资源有占位提示，无无限重试。
- 私网、回环、IPv4-mapped IPv6、混合 DNS、重定向、DNS rebinding 及浏览器子资源绕过均在连接前阻断。
- 超时、响应超限、图片炸弹式大响应、错误 MIME 和代理总预算超限均稳定失败并释放进程/文件。
- 重抓、重新提取或资源完成不会覆盖并发中的人工编辑；冲突路径有 E2E。
- 10 次连续浏览器回退后无遗留 Chromium、代理、临时 context 或下载文件。

**依赖**

- M1 的一致性备份、垃圾回收和可恢复迁移。

**提交 / Review 边界**

- 提交一：`feat(capture): add capture history and safe re-extraction`。
- 提交二：`feat(offline): cache and serve safe article images`。
- 提交三：`feat(capture): add queue controls and duplicate guidance`。
- 安全网关、资源服务和正文替换各自独立 agent 审查；合并前完成服务器真实网页与恶意 fixture 回归。

### M3：知识组织与日常资料库体验（v0.4.0）

**用户价值**

资料从几十篇增长到数千篇后仍能快速找到、批量整理并维护，而无需学习复杂的文件树或图谱。

**具体功能**

- 平面集合：文档可属于多个集合；标签仍用于主题，集合用于项目/用途，避免嵌套树。
- 收藏、归档、回收站视图；批量加/移标签、加入集合、归档、恢复和删除。
- 标签与集合管理：重命名、合并、删除、计数，危险操作预览受影响文档。
- 搜索支持正文、标题、来源、标签、集合、状态、收藏、日期和采集模式筛选，并可按更新时间、创建时间和标题排序。
- 保存最近使用的筛选条件到本机设置；提供“全部、最近、收藏、未整理、归档、失败”固定视图。
- 元数据编辑：标题、作者、发布日期、来源备注；原始采集元数据保留在历史中。
- 列表键盘操作、批量选择、空状态、长标题和长文章性能优化。

**技术工作**

- 追加集合、多对多关系、收藏/归档及来源备注迁移和索引；删除逻辑复用 M1 生命周期。
- 用 SQL 组合过滤、排序和分页，继续使用 SQLite FTS5；不引入搜索服务或客户端状态框架。
- 批量变更使用单事务和统一修订规则，返回逐项结果；避免部分成功后界面误报。
- 标签/集合规范化、大小和数量限制在 API 信任边界执行，UI 只提供提前反馈。
- 对 10,000 篇合成文档建立固定性能基线，记录数据库大小和核心查询延迟。

**验收与测试门槛**

- 标签/集合重命名、合并、批量操作、回收站恢复和分页在事务失败后均不产生半完成状态。
- 中英文短词、长词、特殊字符、URL 和组合筛选结果正确，查询参数无法改变 SQL 语义。
- 10,000 篇基准库中，常用列表/筛选/搜索的服务器端 p95 不高于 300 ms，界面首屏交互不高于 1 s（服务器与浏览器空闲、固定基准环境）。
- 全键盘可完成导入、搜索、选择、编辑、保存、归档和恢复；焦点可见，关键页面无严重无障碍扫描问题。
- 多页批量选择明确作用范围，永不隐式处理未显示结果。

**依赖**

- M1 文档生命周期；M2 采集状态与资源元数据。

**提交 / Review 边界**

- 提交一：`feat(library): add collections and document states`。
- 提交二：`feat(library): add composable filters and bulk actions`。
- 提交三：`feat(ui): complete keyboard-first library workflows`。
- 数据事务与 API、前端交互分别审查；每个提交后在服务器执行 10k 数据集与核心 E2E。

### M4：入口、导入、导出与可迁移性（v0.5.0）

**用户价值**

用户能快速收集已有资料，也能随时把知识完整带走；应用不会形成数据锁定。

**具体功能**

- 单 URL、粘贴多行 URL 和 Netscape `bookmarks.html` 批量导入；导入前预览总数、重复项和非法项。
- 导入 UTF-8 Markdown 文件或目录；识别织页导出的有限 front matter，未知字段保留在正文或明确提示，不猜测复杂格式。
- 导出单篇 Markdown、所选/全部知识 ZIP，以及机器可读 manifest；ZIP 包含 Markdown、离线资源、来源元数据、标签/集合和校验和。
- 完整备份继续使用 M1 的恢复格式，和“供其他工具阅读”的知识导出严格区分。
- macOS 文件打开/拖放导入，`zhiye://capture?url=...` 深链快速捕获，以及单实例转发到现有窗口。
- 导入/导出进度、取消、错误报告和可重复执行；不因单个坏文件丢弃整个批次。

**技术工作**

- 用一个经过许可和安全审查的轻量 ZIP 依赖处理便携包；设置条目数、单文件、总解压大小和压缩比上限，防止 zip bomb 和路径穿越。
- 导入先解析到 staging 表/临时目录并完整校验，再用短事务写入；冲突策略仅提供跳过、保留副本和按来源更新，默认跳过。
- Markdown 导出使用稳定 slug 加随机短 ID 防重名；资源写为相对 `assets/` 路径，manifest 记录格式版本与 SHA-256。
- 深链只接受长度受限的 HTTP/HTTPS URL，忽略其他命令和路径；Tauri Rust 层完成单实例转发，Node 仍执行完整 URL 安全检查。
- 批量采集继续复用 SQLite 队列，并提供硬上限；不引入 Redis 或独立 worker。
- 为导出格式写版本规范和兼容策略；v1.0 必须能重新导入自身导出的包。

**验收与测试门槛**

- “导出全部 → 新数据目录导入”后，正文、元数据、标签、集合和允许类型资源的逐项哈希一致。
- 恶意 ZIP 的绝对路径、`..`、符号链接、超量条目、极端压缩比和校验不符均在写入正式数据前失败。
- 1,000 条 URL/书签输入不会阻塞 UI；重复项和失败项可导出报告并单独重试。
- Markdown 编码错误、重名、非法 front matter 和部分资源缺失都有确定结果，无静默覆盖。
- 冷启动、应用已运行和恶意参数三种深链路径均有 Tauri 集成测试。

**依赖**

- M1 备份/恢复及 staging 清理；M2 离线资源；M3 标签与集合。

**提交 / Review 边界**

- 提交一：`feat(import): add staged bookmark and markdown import`。
- 提交二：`feat(export): add portable knowledge bundles`。
- 提交三：`feat(desktop): add safe capture deep links`。
- 导入器和解压边界必须做独立安全 review；导出提交必须在服务器完成跨数据目录 round-trip 后提交。

### M5：可选 LLM 派生知识（v0.6.0）

**用户价值**

愿意使用模型的用户可以更快获得摘要、提纲和标签建议；不使用模型的用户没有额外网络、成本或数据迁移负担。

**具体功能**

- 默认关闭的文档摘要、分层提纲、关键词和标签建议；用户逐篇触发并预览将发送的文本范围。
- 支持一个 OpenAI-compatible 远程端点和一个显式信任的本地端点；常用远程平台只提供固定地址预设，不做模型市场、Agent 或自动供应商探测。
- 每次结果保存类型、模型、端点标识、提示版本、输入哈希、输出、耗时、token/用量信息（供应商提供时）和时间戳。
- 派生结果与人工正文分离；摘要可固定展示，标签建议必须手动采纳，重新生成不覆盖旧结果。
- 任务可取消、失败可重试；长文按稳定段落分块并明确截断/覆盖范围。
- 设置页显示隐私提示、网络目标和费用风险，可一键关闭并删除派生结果。

**技术工作**

- 新增 `derived_results` 和轻量进程内任务状态；结果以输入哈希去重，不提前建设 Provider 接口层或向量表。
- 远端只允许 HTTPS（localhost 本地端点例外），端点经用户明确保存后加入单独 allowlist；它不能复用网页抓取的“任意公共 URL”输入。
- Web 模式可从成对的端点/密钥环境变量或同源会话中的应用内输入更新当前进程密钥，重启即清除；macOS 桌面由 Rust 从 Keychain 读取端点绑定的密钥并仅传给 sidecar 进程，应用内保存同时更新当前进程。密钥仅发送给精确匹配的规范化端点；数据库、日志、API 响应和导出均不得出现密钥。
- 提示模板版本化；输出按纯文本/Markdown 处理，通过现有安全渲染器显示，不执行模型返回的 HTML 或链接动作。
- 所有自动化测试使用确定性 fake server；真实供应商冒烟为发布前手动、显式授权步骤。

**验收与测试门槛**

- 未配置时不发生模型网络请求；关闭 LLM 时不发送文档或自动生成，只有用户显式点击连接测试才发送固定探针。现有采集/编辑/搜索功能完全可用。
- fake provider 覆盖成功、流式中断、限流、超时、取消、畸形输出、超长输入和应用重启恢复。
- 修改正文后旧结果显示“已过期”，但仍可查看；任何结果都不会修改正文或自动加标签。
- 密钥不出现在 SQLite、备份、导出、结构化日志、错误栈、进程命令行和前端读取接口中。
- 使用本地测试端点完成中文与英文长文摘要冒烟，并验证禁用后无后台调用。

**依赖**

- M3 文档与标签模型；M4 设置/导出边界；用户选择的真实远程供应商仅用于可选发布冒烟。

**提交 / Review 边界**

- 提交一：`feat(ai): store versioned derived results`。
- 提交二：`feat(ai): add opt-in summarization and suggestions`。
- 提交三：`feat(desktop): keep llm credentials in macOS keychain`。
- 密钥流与网络许可必须由安全审查 agent 单独检查；没有外部密钥也必须能通过全部自动门槛并提交。

### M6：质量、安全、性能与发布候选（v0.9.0）

**用户价值**

应用在真实长时间使用、异常网络和升级场景中保持可理解、可恢复且不泄露本地知识。

**具体功能**
