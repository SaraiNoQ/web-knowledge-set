# 支持与故障排查

织页当前为 `0.9.2-rc.2` 功能完整预览版。Apple Silicon DMG 没有 Developer ID 签名或 Apple 公证，不配置更新通道；以下步骤以保护本地数据为第一原则。

## 先保护数据

1. 如果应用还能打开，先到“数据安全”创建完整留档并确认“校验通过”。
2. 如果应用无法打开，停止所有织页/Node/Chromium 进程，再复制整个数据目录及同级 `<数据目录名>-backups` 目录到安全位置。不要只复制正在使用的 `zhiye.sqlite3`。
3. 不要直接编辑数据库、清单、快照、资源或恢复状态文件，也不要反复尝试用旧版本打开较新的数据目录。

默认数据目录和自定义目录规则见 [README.md](./README.md#开始使用)。便携知识 ZIP 只迁移内容；只有“数据安全”创建的完整留档，或由它导出的 `.zhiye-backup`，才可恢复数据库、快照和离线图片。

## 诊断信息

在“数据安全 → 诊断台”查看版本、schema、队列、完整性、文件异常和稳定错误码。需要提供给维护者时，可导出诊断包，但必须先解压并人工检查其中的 `diagnostics.json`、`logs.jsonl` 和 `README.txt`。

不要上传或粘贴以下内容：

- `zhiye.sqlite3`、`-wal`、`-shm` 或完整备份；
- `snapshots/`、`assets/`、便携知识包或原始 Markdown；
- Cookie、一次性启动 URL、API 密钥、钥匙串内容或环境变量；
- 未经人工检查的诊断包。

普通问题可在 <https://github.com/SaraiNoQ/web-knowledge-set/issues> 提交，附上版本、操作系统、可复现步骤、预期/实际结果和已脱敏错误码。安全问题请按 [SECURITY.md](./SECURITY.md#报告安全问题) 私下报告。

## 常见问题

### 本地 Web 显示未授权或无法连接

- 确认服务仍在运行，并使用本次启动终端打印的完整 `ZHIYE_READY` 地址；旧令牌和只访问端口根地址不能建立新会话。
- 只有管理员明确配置的 `KB_TRUST_LOCALHOST=1` 预览服务可直接打开根地址。该模式信任能连入服务器 localhost 的用户，只能经受信 SSH 隧道使用，不得与 `KB_DEV=1`、桌面 sidecar、`0.0.0.0` 或反向代理并用。
- 服务只监听 `127.0.0.1`。远端开发时先建立 SSH 隧道，再打开完整一次性地址；不要改为监听 `0.0.0.0`。
- 同一数据目录一次只能由一个实例使用。完全退出另一个 Web/桌面实例后重试。

### 固定 Web 预览服务迁移与回退

固定预览只允许安装到 `/opt/zhiye-preview`，数据只放在 `/var/lib/zhiye-preview/data`，并由无登录用户 `zhiye-preview` 运行。切换前必须在旧服务的“数据安全”中创建完整留档并再次校验为 `verified`；然后正常停止旧进程，确认 `127.0.0.1:4301` 已无监听，才能冷复制整个数据目录。不得复制仍在运行的 SQLite，也不得让部署脚本自动杀死未知占用者。

```sh
pnpm desktop:prepare
scripts/deploy-web-preview.sh stage <完整提交 SHA> .

# 旧进程完全退出后，且目标目录确认为空时执行一次。
test -z "$(find /var/lib/zhiye-preview/data -mindepth 1 -print -quit)"
cp -a /root/zhiye-web-preview-data/. /var/lib/zhiye-preview/data/
test ! -e /var/lib/zhiye-preview/data-backups
test ! -L /var/lib/zhiye-preview/data-backups
runuser -u zhiye-preview -- mkdir -m 0700 /var/lib/zhiye-preview/data-backups
cp -a /root/zhiye-web-preview-data-backups/. /var/lib/zhiye-preview/data-backups/
chown -R zhiye-preview:zhiye-preview /var/lib/zhiye-preview

scripts/deploy-web-preview.sh activate <完整提交 SHA>
```

`activate` 只有在 systemd 主进程属于 `zhiye-preview`，且数据安全接口确认正常模式、数据库完整、无外键及缺失/不安全文件问题时才完成；新版本失败会恢复先前的 `current`。旧 root 数据和留档原目录至少保留七天，不在切换脚本中删除。需要人工回退时执行 `scripts/deploy-web-preview.sh rollback <旧提交 SHA>`，再核验资料数量、数据库完整性和无孤儿 Node/Chromium 进程。

最终 RC 激活后，以 root 启动 24 小时记录器；它只写时间、稳定状态和计数，不写会话 Cookie、标题或文件路径。默认每 5 分钟采样一次，只接受以字母或数字开头、其余为字母、数字、点、下划线或连字符的记录名，并在严格由 root 所有、权限为 `0700` 的 `/var/lib/zhiye-preview-evidence` 下创建同名目录；已有目录的类型、所有者或权限不符时会直接拒绝，不会自动修复：

```sh
scripts/soak-web-preview.sh rc-0.9.2

# summary.json 显示 complete=true 且 pass=true 后，再执行明确重启与复验。
systemctl restart zhiye-preview.service
scripts/soak-web-preview.sh --verify-restart rc-0.9.2
```

归档对应记录目录中的 `samples.jsonl`、`summary.json` 和 `restart-verification.json`；最后一份必须显示新 MainPID 且 `pass=true`。长跑期间发生 MainPID 变化、发现孤儿进程，或临时文件体积连续增长至少一小时，都会使汇总失败。短时验证可显式传入持续秒数和采样间隔，例如 `scripts/soak-web-preview.sh check-600s 600 30`，不能把短时结果记作最终 soak。

### 正式身份升级后提示两个知识库

`0.9.1` 只在旧 `dev.local.zhiye` 与正式 `io.github.sarainoq.zhiye` 位置中有且只有一个知识库时自动继续使用原数据。若两边都有内容，或只剩备份、诊断或锁文件而缺少主数据目录，应用会停止而不猜测。不要删除或合并 SQLite 文件；先完整保留新旧目录及同级的 `-backups` / `-diagnostics`，用能打开对应数据的构建创建并校验完整留档，再恢复到明确选定的空目录。本地 Web 模式可在停止服务后用 `KB_DATA_DIR` 明确选择其中一个。

### 网页采集失败或正文不完整

- 只提交公开、不含账号密码的 HTTP/HTTPS URL。登录态、付费墙、验证码、PDF、内网地址和整站爬取不受支持。
- 查看采集历史中的稳定错误码、HTTP 状态和模式。网络恢复后可手动重试；已有 HTML 快照时可选择“从快照重新提取”并先比较候选内容。
- 直接读取受 15 秒、5 次重定向、5 MiB 限制；浏览器回退受 30 秒、25 MiB 网络预算和 5 MiB 最终 HTML 限制。超过限制不是可通过重复重试解决的问题。
- 重新采集、重新提取或 AI 都不会自动覆盖人工正文；只在差异预览中明确采纳需要的字段。
- 对必须登录后才能阅读的网页，可在云端织页“帮助 → 浏览器扩展”下载当前 `0.2.2` Chrome/Firefox 剪藏扩展并生成一次性配对码。扩展只连接 `https://clip.sarainoq.cn`，读取用户点击时的当前标签页；确认 Markdown 后创建新副本。KaTeX/MathML 渲染的公式会恢复为可编辑的 `$…$` 或 `$$…$$` TeX；保存前仍应在扩展预览中核对正文。Chrome 解压后使用“加载已解压的扩展程序”，Firefox 解压后从 `about:debugging` 临时加载 `manifest.json`。Firefox 正式持久安装仍需未来 AMO 签名。
- 撤销配对后扩展会在下次保存时报未授权；在扩展中重新输入新配对码即可。扩展无法处理浏览器内部页、PDF 或空正文，此时使用“手动摘录正文”。

### 文章图片无法离线显示

只缓存 JPEG、PNG、GIF、WebP 和 AVIF，且服务器声明的类型必须与文件签名一致。默认每张 10 MiB、每篇 100 张、合计 100 MiB。SVG、视频、需要 Cookie 的图片、非公网图片和失败请求不会缓存；Markdown 仍保留原始 URL，但预览不会为了失败图片偷偷回连原站。

### 编辑内容未保存或发生冲突

等待保存状态完成，或按 `Command/Ctrl + S`。多个窗口同时编辑时，409 冲突会保留双方版本而不自动合并；先复制需要保留的本地内容，再根据界面选择服务端版本或重新应用修改。不要通过直接编辑 SQLite 解决冲突。

### AI 无法生成

- 确认已在“AI 设置”显式开启、配置模型和端点，并在文档中预览发送范围后勾选确认。
- 先在模型设置下点击“测试连接”。它只发送固定探针，不发送文档或保存当前表单；远程测试需要已为该精确端点保存密钥，并可能产生小额费用。
- 翻译支持不超过 100 万编辑器字符、5,000 个可译段和 64 个批次；界面会逐批显示准确发送文本。批次顺序请求且不会后台重试，任一批失败或取消都不保存半成品，手动重试会从第一批开始。
- 如果模型缺失、重复或新增片段 ID，或译文改变 Markdown 结构，结果会被拒绝；请使用能稳定返回 JSON 的模型重试。
- 远程模式可直接选择内置平台；只有列表中没有目标平台时才选择“其他”并输入无查询参数/凭据的 HTTPS 公网地址。
- 在平台下方输入并单独保存 API Key。密钥只绑定当前所选端点；切换平台或手动地址后必须重新录入。Web 端只保留到当前服务进程重启；macOS 桌面端同时写入系统钥匙串并立即更新当前进程。也可在 Web 服务启动前成对设置 `ZHIYE_LLM_API_KEY` 与 `ZHIYE_LLM_API_ENDPOINT`，只设置其中一个不会加载密钥。
- Cloudflare Web 的 API Key 只保留在当前页面内存，刷新或关闭页面后需重新输入；云端只接受内置 HTTPS 平台。云端翻译当前上限为 40,000 字符，更长文章使用本地 Web/桌面端的分批翻译。
- 本地端点只能使用 `localhost` 或 loopback IP，并必须明确勾选信任。端点进程可以读取所发送的正文。
- 模型请求不会后台重试。错误后检查端点、网络、配额和稳定错误码，再手动重试。

### 数据库损坏或进入恢复模式

不要删除当前目录。恢复模式只开放数据安全和诊断能力：选择一份“校验通过”的完整留档恢复。应用会验证清单、哈希、schema 与空间，并优先创建恢复前留档；如果当前数据已损坏到无法备份，只有在确认提示后才允许把原目录整体隔离，再启用所选备份。

恢复完成后检查数据库完整性、外键、缺失文件和最近文档。如果没有可验证备份，先保留整个故障目录，再提交不含真实数据的错误码寻求帮助。

### 用完整留档文件换机

1. 在原设备的“数据安全”创建留档，确认状态为“校验通过”，再选择“导出文件”。
2. `.zhiye-backup` 未加密且包含完整知识数据；它不包含 API 密钥。只通过受信存储介质移动，不要上传到 issue 或公开网盘。
3. 在新设备的“数据安全”选择“导入留档文件”。织页仅接受不超过 2 GiB、50,000 个条目且路径、CRC、清单、SHA-256、schema 和空间校验全部通过的严格格式。
4. 导入只会在留档列表新增“校验通过”记录，不会覆盖当前资料。确认日期和大小后，再明确点击“恢复此留档”并接受二次确认。

如果出现结构、路径、链接、校验值、schema 或空间错误，不要修改 ZIP 内容或反复导入；从原设备重新创建并导出留档。导入失败不会改变当前资料。

Cloudflare Web 使用 `.zhiye-cloud-backup`：在“数据安全”创建并导出，新环境导入后再明确点击恢复。当前 v2 会保存一级文件夹与文档归属，并继续接受 v1（其文档恢复为“未分类”）；上限为 8 MiB/合计 32 条文件夹、文档与 AI 结果，不与本地 `.zhiye-backup` ZIP 混用。恢复会撤销旧扩展配对，需重新配对。

## 更新失败与版本回退

源码和未签名构建只能人工更新；正式签名构建才会启用应用内更新。人工更新前：

1. 在当前版本创建并校验完整留档；保留当前应用/提交 SHA 和备份。
2. 完全退出应用，确认没有正在运行的 Node 或 Chromium，再安装或启动新版本。
3. 新版本第一次打开可能先创建迁移前备份，然后只向前迁移数据库。

如果新版本在迁移前失败，可以退出新版本后重新打开旧版本。如果新版本已经迁移数据库，**不要**让旧版本直接打开升级后的数据目录，也不要手工降低 schema；旧版本会拒绝未来 schema，这是数据保护机制。

需要回退时，先保留升级后的完整目录，然后在独立的空数据目录中使用与旧版本兼容的、更新前完整备份。若不确定备份 schema 是否兼容，继续使用新版本恢复，或先提交版本、当前/支持 schema 和错误码寻求帮助。便携知识包可用于跨版本迁移内容，但不能替代数据库恢复。

正式签名 updater 会要求用户确认并先创建校验通过的完整留档；下载或签名失败时保留当前版本。没有签名更新通道的构建应继续按人工更新流程排查。

## 卸载

卸载应用本体不会自动删除知识。确认已取得需要的完整备份或便携导出后，分别处理数据目录、同级 `-backups`、同级 `-diagnostics`、桌面启动器配置和 macOS 钥匙串中的模型密钥。删除这些内容不可恢复；不确定路径时不要猜测或使用递归删除命令。
