# 支持与故障排查

织页当前为 `0.9.1` 发布候选构建，尚无签名、公证的正式 macOS 安装包。源码和未签名构建不配置更新通道；以下步骤以保护本地数据为第一原则。

## 先保护数据

1. 如果应用还能打开，先到“数据安全”创建完整留档并确认“校验通过”。
2. 如果应用无法打开，停止所有织页/Node/Chromium 进程，再复制整个数据目录及同级 `<数据目录名>-backups` 目录到安全位置。不要只复制正在使用的 `zhiye.sqlite3`。
3. 不要直接编辑数据库、清单、快照、资源或恢复状态文件，也不要反复尝试用旧版本打开较新的数据目录。

默认数据目录和自定义目录规则见 [README.md](./README.md#开始使用)。备份不是便携知识 ZIP；只有“数据安全”创建的完整留档可恢复数据库、快照和离线图片。

## 诊断信息

在“数据安全 → 诊断台”查看版本、schema、队列、完整性、文件异常和稳定错误码。需要提供给维护者时，可导出诊断包，但必须先解压并人工检查其中的 `diagnostics.json`、`logs.jsonl` 和 `README.txt`。

不要上传或粘贴以下内容：

- `zhiye.sqlite3`、`-wal`、`-shm` 或完整备份；
- `snapshots/`、`assets/`、便携知识包或原始 Markdown；
- Cookie、一次性启动 URL、API 密钥、钥匙串内容或环境变量；
- 未经人工检查的诊断包。

普通问题可在 <https://github.com/SaraiNoQ/web-knowledge-set/issues> 提交，附上版本、操作系统、可复现步骤、预期/实际结果和已脱敏错误码。安全问题请按 [SECURITY.md](./SECURITY.md#报告安全问题) 私下报告。

## 常见问题

### 本地 Web 显示未授权或无法连接

- 确认服务仍在运行，并使用本次启动终端打印的完整 `ZHIYE_READY` 地址；旧令牌和只访问端口根地址不能建立新会话。
- 服务只监听 `127.0.0.1`。远端开发时先建立 SSH 隧道，再打开完整一次性地址；不要改为监听 `0.0.0.0`。
- 同一数据目录一次只能由一个实例使用。完全退出另一个 Web/桌面实例后重试。

### 正式身份升级后提示两个知识库

`0.9.1` 只在旧 `dev.local.zhiye` 与正式 `io.github.sarainoq.zhiye` 位置中有且只有一个知识库时自动继续使用原数据。若两边都有内容，或只剩备份、诊断或锁文件而缺少主数据目录，应用会停止而不猜测。不要删除或合并 SQLite 文件；先完整保留新旧目录及同级的 `-backups` / `-diagnostics`，用能打开对应数据的构建创建并校验完整留档，再恢复到明确选定的空目录。本地 Web 模式可在停止服务后用 `KB_DATA_DIR` 明确选择其中一个。

### 网页采集失败或正文不完整

- 只提交公开、不含账号密码的 HTTP/HTTPS URL。登录态、付费墙、验证码、PDF、内网地址和整站爬取不受支持。
- 查看采集历史中的稳定错误码、HTTP 状态和模式。网络恢复后可手动重试；已有 HTML 快照时可选择“从快照重新提取”并先比较候选内容。
- 直接读取受 15 秒、5 次重定向、5 MiB 限制；浏览器回退受 30 秒、25 MiB 网络预算和 5 MiB 最终 HTML 限制。超过限制不是可通过重复重试解决的问题。
- 重新采集、重新提取或 AI 都不会自动覆盖人工正文；只在差异预览中明确采纳需要的字段。

### 文章图片无法离线显示

只缓存 JPEG、PNG、GIF、WebP 和 AVIF，且服务器声明的类型必须与文件签名一致。默认每张 10 MiB、每篇 100 张、合计 100 MiB。SVG、视频、需要 Cookie 的图片、非公网图片和失败请求不会缓存；Markdown 仍保留原始 URL，但预览不会为了失败图片偷偷回连原站。

### 编辑内容未保存或发生冲突

等待保存状态完成，或按 `Command/Ctrl + S`。多个窗口同时编辑时，409 冲突会保留双方版本而不自动合并；先复制需要保留的本地内容，再根据界面选择服务端版本或重新应用修改。不要通过直接编辑 SQLite 解决冲突。

### AI 无法生成

- 确认已在“AI 设置”显式开启、配置模型和端点，并在文档中预览发送范围后勾选确认。
- 翻译要求完整文档及片段 JSON 均不超过 40,000 字符，不会对超长文档做部分翻译。
- 如果模型缺失、重复或新增片段 ID，或译文改变 Markdown 结构，结果会被拒绝；请使用能稳定返回 JSON 的模型重试。
- 远程端点必须是无查询参数/凭据的 HTTPS 公网地址；Web 模式启动服务前设置 `ZHIYE_LLM_API_KEY`，桌面端在 macOS 钥匙串保存后完全退出并重开。
- 本地端点只能使用 `localhost` 或 loopback IP，并必须明确勾选信任。端点进程可以读取所发送的正文。
- 模型请求不会后台重试。错误后检查端点、网络、配额和稳定错误码，再手动重试。

### 数据库损坏或进入恢复模式

不要删除当前目录。恢复模式只开放数据安全和诊断能力：选择一份“校验通过”的完整留档恢复。应用会验证清单、哈希、schema 与空间，并优先创建恢复前留档；如果当前数据已损坏到无法备份，只有在确认提示后才允许把原目录整体隔离，再启用所选备份。

恢复完成后检查数据库完整性、外键、缺失文件和最近文档。如果没有可验证备份，先保留整个故障目录，再提交不含真实数据的错误码寻求帮助。

## 更新失败与版本回退

源码和未签名构建只能人工更新；正式签名构建才会启用应用内更新。人工更新前：

1. 在当前版本创建并校验完整留档；保留当前应用/提交 SHA 和备份。
2. 完全退出应用，确认没有正在运行的 Node 或 Chromium，再安装或启动新版本。
3. 新版本第一次打开可能先创建迁移前备份，然后只向前迁移数据库。

如果新版本在迁移前失败，可以退出新版本后重新打开旧版本。如果新版本已经迁移数据库，**不要**让旧版本直接打开升级后的数据目录，也不要手工降低 schema；旧版本会拒绝未来 schema，这是数据保护机制。

需要回退时，先保留升级后的完整目录，然后在独立的空数据目录中使用与旧版本兼容的、更新前完整备份。若不确定备份 schema 是否兼容，继续使用新版本恢复，或先提交版本、当前/支持 schema 和错误码寻求帮助。便携知识包可用于跨版本迁移内容，但不能替代数据库恢复。

正式签名 updater 会要求用户确认并先创建校验通过的完整留档；下载或签名失败时保留当前版本。没有签名更新通道的构建应继续按人工更新流程排查。

## 卸载

卸载应用本体不会自动删除知识。确认已取得需要的完整备份或便携导出后，分别处理数据目录、同级 `-backups`、同级 `-diagnostics`、桌面启动器配置和 macOS 钥匙串中的模型密钥。删除这些内容不可恢复；不确定路径时不要猜测或使用递归删除命令。
